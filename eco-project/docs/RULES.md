# Правила разработки для AI моделей

## 📝 Перед каждым ответом

1. **Проверь контекст**
   - Открыта ли `ARCHITECTURE.md`?
   - Знаешь ли структуру проекта из `PROJECT_STRUCTURE.md`?
   - Знаешь ли типы данных из `DATA_STRUCTURES.md`?

2. **Токен-оптимизация**
   - Не переписывай файл целиком, если меняется 5 строк
   - Используй пути вместо кода: "смотри `scripts/core/player.gd` линия 42"
   - Для больших описаний - ссылайся на документацию

3. **Ошибки которые приводят к багам**
   - ❌ Создание скрипта без указания в ARCHITECTURE.md
   - ❌ Прямое общение между сценами без EventBus
   - ❌ UI скрипт с игровой логикой
   - ❌ Жесткие пути вместо NodePath

## 💡 Структура ответа

```
## [Что делаем]

### Файлы для изменения
- `path/to/file.gd` - что там меняем

### Код
[Только измененные части]

### Проверка
- [ ] Консистентно с ARCHITECTURE.md?
- [ ] Новые сигналы добавлены в EventBus?
- [ ] Типы данных совпадают с DATA_STRUCTURES.md?
```

## 🔄 Поток разработки

1. **User запрос** → Feature request
2. **AI анализ** → Проверка архитектуры
3. **AI план** → Какие файлы меняем
4. **AI код** → Только измененные части
5. **Проверка** → Контрольный список

## ⚠️ Критические ошибки

| Ошибка | Последствие | Как избежать |
|--------|------------|-------------|
| Прямое общение сцен | Race conditions | Используй EventBus всегда |
| Хардкодированные пути | Сломается при рефакторинге | Используй `get_node()` или NodePath |
| Смешивание слоев | Сложно тестировать | Четко разделяй: Game/UI/Data |
| Большой ответ | Потеря контекста | Ссылайся на документацию |

## 📊 Метрики успеха

- ✅ Каждый новый скрипт описан в документе
- ✅ Новые сигналы только в EventBus
- ✅ UI не знает о game logic
- ✅ Ответы < 500 слов по возможности
- ✅ Все типы данных типизированы
